*** BEGIN SPEC AbsTreeNode ***
AbsTreeNode

This class should implement all of the functionality that is common to all of its implementing subtypes.

This is an abstract class to serve as a base class and cannot itself be instantiated.

All of the attribute state holding members should be private and only assessable by getter methods.

Each of these attributes will be set-able via private setter methods.

The instance construction process for any AbsTreeNode sub-type needs to :
Capture the state of the name and parent in the instance being constructed
Ensure that the name is unique across the set of all instances of the AbsTreeNode
subtype created in the running instance of the controlling interpreter.
When classes are loaded, the state used to enforce uniqueness of name values across AbsTreeNode subtype classes is reset.
If a parent is provided, it needs to ensure that the parent is of the same class as the instance being created.  As a counter-example, a BusinessUnit instance cannot be the parent of a Space instance, e.g., :
bu = BusinessUnit("Department")
... st = SpaceType("Gondola")
... s = Space(st, bu) -- No no

The instance being created will give itself to the parent to be added as its child,
 
Regarding implementation, a dict{str,<<implementing AbsTreeNode subtype class name>>] where the key is the name and the <<implementing AbsTreeNode subtype class name>> is the set of instances of the implementing subtype with the name given. This dict instance should live in the loaded AbsTreeNode class. </p>
At construction, after the state of the instance has been validated, if the instance name exists in the in the uniqueness-checking dict then a ValueError is thrown.
Otherwise a new entry is made in the dict with the name and a reference to the new instance.

add_child 

Example Abstract Usage:
imp_class = <<implementing subclass of AbsTreeNode>>
p = imp_class(name1...) -- Create instance serving as the parent.
...
c = imp_class(name2,p) -- Create instance serving as the child to parent p
     ---> p.add_child(c) -- add_child is accessed from the imp_class constructor and lives in AbsTreeNode.



Example in the context of this sim:

class ProductCategory(AbsTreeNode): ...

pc_root = ProductCategory(name: "Products")  -- A root (no parent) category containing base categories, like "Baby Food" (not necessarily consistent with actual business requirements).
...
baby_food = ProductCategory(name: "Baby Food", pc_root)
baby_meats = Product(Category(name: "Baby Meats",parent: baby_food)
    -- From the baby meats instance construction, invoke:
    ---> parent.add_child(self)
