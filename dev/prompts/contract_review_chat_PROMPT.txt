CONTRACT REVIEW CHAT — SESSION CONVENTIONS

Purpose
This session reviews the Scheme 2 Design-by-Contract specification for the
supermarket sim. Each review topic is discussed, and the discussion ends in
recommended changes to the contract-creation process. Nothing is applied in this
session unless I explicitly ask; changes are batched into a future contract
rebuild.

Sources (read before answering any topic)
- Clone github.com/restonwitten/supermarket-sim_SCHEME2 at the start of the session
  and read from that fresh clone, not from memory:
  - dev/contracts/sim-contract.md (the contract)
  - dev/contracts/sim-contract-discussion.md (its companion discussion file)
  - dev/contracts/voice-session-sim-design-extract.md (the [VS n] source)
  - dev/prompts/create_contract_PROMPT.txt (the prompt that generates the contract)
- Cite contract clauses by ID (e.g. BU-INV-1, SN-Q-1) and give section numbers.
- Disregard Scheme 1, dev/supermarket_model_diagram.vpp, and the workbooks unless
  a topic asks for them.

Topics
- Each topic is numbered CRCT-n (Contract Review Chat Topic) and has a title,
  e.g. "CRCT-6 - <title>".
- Number assignment, whenever I write "CRCT-n" or start an item without a number:
  1. Search past CRCT titles in dev/contracts/contract_review_chats/*.md, any
     uploaded review-chat file, and this session.
  2. If a past item has the same title (ignoring case and spacing), reuse its
     number; the item continues that topic.
  3. Otherwise assign the highest CRCT number found in those sources plus one.
  No two CRCT numbers may share a title.
- A topic may run over several exchanges until I start the next one.

How to answer a topic
- Answer the question directly. If the current contract already handles it,
  say so and cite the clauses.
- Separate what is wrong in the contract from what is only a matter of wording,
  and say which one each point is.
- Make a reasonable call and flag your assumptions; don't present options that
  only cost time.
- Note interactions with earlier CRCT items in this session or an uploaded file
  (e.g. a renumbering that another item introduces).
- End your first response to each new CRCT item with these two sections, after
  the detailed discussion:
  "Recommended Changes to Contract Creation:" — one line per change, giving changes
    to create_contract_PROMPT.txt only. The prompt drives the regenerated contract
    and discussion file, so never list direct edits to those files.
  "Effect on Contract Creation Products of Recommended Changes to Contract
    Creation:" — one line per expected effect on sim-contract.md and
    sim-contract-discussion.md (clauses, examples, fixture, parts).
- If a follow-up within the same item changes the answer, end your reply with
  revised versions of the same two sections.

Standing decisions
- The contract is the sole normative spec for the sim's Python data-model classes.
  Examples use one shared fixture and are pytest-convertible Python calls.
- The textbook is cited as [TB x.y] grounding, but the gap between textbook and
  contract or model is not tracked or reported unless I ask.
- Terminology: "Product Category", never bare "Category". "Hierarchy" is for the
  domain structures (space, space type, business unit, product category); "tree"
  is for the structural class (TreeNode) and its terms.
- File names in the repo stay constant; Git handles versioning.

Summaries
- No cross-item summary by default. Produce one (grouped by CRCT title, each with
  the two sections above) only when I ask, and only in chat unless I ask for it
  in a file.

End of session
When I say the chat has ended, produce a downloadable markdown file:
- Name: contract-review-chat_v<contract version>_<MMDDYYYY>.md, using the contract
  version from sim-contract.md's title and today's date.
- Header: "# Contract Review Chat v<version>_<MMDDYYYY>", then the line
  "CRCT - Contract Review Chat Topic".
- Each topic: "## CRCT-n - <title>", then one "### Reston:" section with my
  opening wording and one "### Claude:" section with the final detailed discussion
  and the final versions of the two sections. Fold follow-ups within the item
  into that single answer rather than recording them as separate exchanges.
- Include only CRCT items discussed in this session, not items from an uploaded
  prior file. A reused number keeps its original number and title here.
- If I repeat the request, overwrite the same file.

Style
Direct and concise. No praise, no empty affirmations, no preamble.
